
# PHP Lab

[![PHP CI Application](https://github.com/vika-synyshyn/php-lab/actions/workflows/php-ci.yml/badge.svg?branch=main)](https://github.com/vika-synyshyn/php-lab/actions/workflows/php-ci.yml)

Навчальний PHP-проєкт, призначений для практичного освоєння систем керування версіями, автоматизованого тестування та технологій безперервної інтеграції й розгортання (CI/CD).

## Мета проєкту

Розроблення PHP-застосунку з використанням Git та GitHub для контролю версій, організації командної роботи й автоматизації перевірки програмного коду.

Проєкт демонструє налаштування автоматизованого CI-пайплайну, використання модульного тестування, статичного аналізу коду та механізмів захисту головної гілки репозиторію.

## Функціональність

- Керування версіями програмного коду за допомогою Git.
- Організація командної розробки через GitHub Pull Requests.
- Реалізація PHP-класу Calculator з арифметичними операціями.
- Модульне тестування методів додавання та віднімання.
- Автоматизований запуск тестів із використанням PHPUnit.
- Перевірка форматування PHP-коду за допомогою Laravel Pint.
- Налаштування CI-пайплайну на основі GitHub Actions.
- Захищене зберігання конфіденційних даних через GitHub Secrets.
- Захист головної гілки за допомогою Branch Protection Rules.
- Управління завданнями через GitHub Issues та Projects.

## Використовувані технології

- **PHP 8.2** — мова програмування.
- **Git** — система керування версіями.
- **GitHub** — платформа для зберігання коду та командної роботи.
- **GitHub Actions** — автоматизація CI-процесів.
- **Composer** — менеджер залежностей PHP.
- **PHPUnit 10** — фреймворк модульного тестування.
- **Laravel Pint** — інструмент перевірки та форматування PHP-коду.
- **YAML** — формат конфігурації CI-пайплайну.

## Встановлення та запуск

### 1. Клонування репозиторію

```bash
git clone https://github.com/vika-synyshyn/php-lab.git
cd php-lab
```

### 2. Встановлення залежностей

Для локального запуску необхідно мати встановлені PHP 8.2 та Composer.

```bash
composer install
```

Composer встановить бібліотеки, визначені у файлі `composer.json`, зокрема PHPUnit та Laravel Pint.

### 3. Перевірка форматування коду

Для перевірки відповідності PHP-коду стандартам форматування виконайте:

```bash
./vendor/bin/pint --test
```

Команда перевіряє форматування без автоматичного внесення змін до файлів.

Для автоматичного виправлення форматування можна використати:

```bash
./vendor/bin/pint
```

### 4. Запуск модульних тестів

Для запуску тестів PHPUnit виконайте:

```bash
./vendor/bin/phpunit --bootstrap vendor/autoload.php tests/Unit
```

Тести перевіряють правильність роботи методів:

- `add(2, 3)` — очікуваний результат `5`.
- `subtract(5, 2)` — очікуваний результат `3`.

## Автоматизація CI через GitHub Actions

У проєкті налаштовано CI-пайплайн **PHP CI Application**, конфігурація якого знаходиться у файлі `.github/workflows/php-ci.yml`.

Пайплайн автоматично запускається за таких подій:

- `push` — надсилання змін до гілки `main`.
- `pull_request` — створення або оновлення Pull Request до гілки `main`.

### Основні етапи CI-пайплайну

1. **Checkout repository** — завантаження вихідного коду.
2. **Set up PHP** — налаштування середовища PHP 8.2.
3. **Install Dependencies** — встановлення бібліотек через Composer.
4. **Demonstrate GitHub Secrets** — демонстрація захищеного використання секретів.
5. **Lint code with Pint** — автоматична перевірка форматування PHP-коду.
6. **Run unit tests** — запуск модульних тестів PHPUnit.

Усі етапи виконуються на сервері GitHub Actions із використанням середовища `ubuntu-latest`.

## Безпека та контроль якості

Для забезпечення безпеки і стабільності розробки використовуються:

- **GitHub Secrets** — захищене зберігання конфіденційних параметрів.
- **Branch Protection Rules** — обмеження злиття змін до головної гілки без проходження обов'язкових перевірок.
- **Pull Request Review** — механізм перевірки змін перед інтеграцією.
- **Laravel Pint** — автоматизований контроль форматування коду.
- **PHPUnit** — тестування програмної логіки.

## Результати тестування

Під час налаштування CI-пайплайну було перевірено механізм автоматичного виявлення помилок.

Laravel Pint виявив порушення форматування PHP-коду, зокрема неправильні відступи, відсутність пробілів навколо операторів та некоректний порядок імпортів.

Після виправлення цих порушень було усунуто помилки оголошення просторів імен PHP, які перешкоджали запуску модульних тестів.

Повторне виконання CI-пайплайну завершилося успішно. Перевірки форматування Laravel Pint та модульні тести PHPUnit пройдено.
